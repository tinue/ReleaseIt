# Changelog

## [0.1.0] - work in progress

- **First version**: one `release` command driven by `release.yaml`, replacing the per-project `bin/release` scripts of Calc-U-59 (macOS + iOS), Calc-U-1600, SharpDataExchange and VolumePruner.
- **Release cycle**: `release` (pre-release under `vX.Y.Z-pre`), `--rc` (dates the CHANGELOG entry), `--reopen` (undoes `--rc`'s date), `--release` (squash-merge to main, retarget the pre-release onto `vX.Y.Z` in place), `--next` (cut the next dev branch, bump the version), `--build-only`, `--dry-run`.
- **Build steps**: `commands`, `xcode-dmg` (local Developer ID DMG with notarization), `github-dispatch` and `github-tag-push`, combinable; all assets go into one pre-release.
- **App Store**: `whatsnew.txt` generation during pre-releases, `release ios` for TestFlight and App Store Connect setup (metadata, screenshots, build).
- **iPhone Duo screenshots**: `release ios --release` uploads `iphoneduo-NN-*.png` as the `APP_IPHONE_DUO` set (outer 1398×2034 or inner 2007×2853 display, either orientation). Apple's API reference doesn't list the type yet, but the live API accepts it.
- **`renew-certs`**: a second tool that rotates the Developer ID certificates CI signs with. It exports the newest G2 identities from the keychain under a fresh random password, checks them, sets the `.p12` and password secrets of the project it runs in (configured by a `certs:` section in `release.yaml`), and records SHA-1 and expiry as repo variables; `status` reports what CI has and when it expires, and `backup` stores the identities in 1Password (Private vault).
- **A re-cut pre-release holds exactly the new build**: assets an earlier run uploaded under another name are removed, and only this build's assets are installed on this Mac.
- **`release.post_release`**: shell commands run after a successful `release`, `--rc` or `--release`, for example to install the built app.
- **Install on this Mac**: after `release` and `--rc`, the `.app` of every `.dmg` asset goes into `/Applications` (signature and Gatekeeper checked, a running copy quit and restarted; an asset that cannot be installed is a warning, the release still succeeds), and the binaries listed under `release.install.binaries` (an archive asset and the path inside) into `~/.local/bin`; assets only CI produced are downloaded from the pre-release.
- **Several products in one repository**: `release -C <product dir>` takes a `release.yaml` there as the project root; `tag_prefix` prefixes every tag, `branching: trunk` releases from main without dev branches or a squash (`--release` tags the pre-release's commit, `--next` bumps in place), `maintenance_branches` allows patch releases from branches such as `calc-u-59/2.4.x`, and `release.latest: false` keeps GitHub's "Latest" off.
- **App Store notes**: CHANGELOG lines marked `<!-- appstore: skip -->` stay out of `whatsnew.txt`, lines marked `<!-- appstore: only -->` out of the GitHub notes; `appstore.notes_forbidden` stops a release whose App Store notes still name a listed word (e.g. other platforms).
